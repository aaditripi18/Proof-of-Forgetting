When a client asks a federated learning server to forget its data, the server typically supports its claim with a membership-inference test showing that the client can no longer be detected in the model. We ask what such tests can certify, by running five verifiers against a server that did nothing at all, against genuine retrains without the client, and against a dishonest server that never unlearns but suppresses the client's backdoor canary. On CIFAR-10 (six seeds) and PathMNIST (three seeds) with ten non-IID clients, the loss-threshold membership AUC most often reported for unlearning cannot tell the server that did nothing from a genuine retrain on any run (AUC 0.48-0.55 for every model). Client-level LiRA, judged against ten retrains without the client, separates them with one false alarm in 70 tests on genuine retrains, but only when the client contributed enough data. Cutting a single client's training data while holding the federation fixed shows that this size is the cause: no client cut to 1000 samples or fewer was detected (0/6), while every client with 3000 or more was (6/6). The threshold is not a constant: training the federation longer (76-79% instead of 61-67% test accuracy) made a 1855-sample client detectable. Backdoor canaries are no safer: they flagged a genuine retrain in 7 of 18 tests, and a server that reconstructs and erases the trigger with Neural Cleanse passed the canary check on 2 of 9 runs and LiRA on 3 of 9. No single verifier caught the dishonest server on every run. Every reported number is traceable to the run that produced it, and the code and results are public.
